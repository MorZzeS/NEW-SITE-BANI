## Реализовано

- Сохранён существующий CTA и его контакты. Под gate подготовлена единая форма для модели, главной, контактов, конфигуратора. Источник, модель, артикул, очищенный URL и выбранная комплектация передаются по контракту v3. Exit-intent передаёт источник и акцию 15 000 ₽; для известного дома акция не назначается. Модель можно восстановить по slug исходной страницы.
- Неотмеченное согласие, показ точных утверждённых текстов, проверка версий и SHA-256. Пока подлинный утверждённый пакет отсутствует, отправка недоступна.
- Новый opt-in обработчик рядом с прежним `leads-server.mjs`; прежний backend не изменён. Валидация/доставка MAX адаптированы для постоянного хранения. SQLite сохраняет заявку, квитанцию, точные тексты согласий и outbox атомарно. Документы архивируются по версиям и хешам.
- requestId + fingerprint: тот же запрос возвращает прежнюю квитанцию после перезапуска, изменённый payload конфликтует. Нет обещания exactly-once.
- HTTP 202 означает «сохранено, ожидает доставки», а не «доставлено». Только подтверждённый ответ MAX с message ID означает sent. Тайм-аут, неясный ответ и прерванная отправка переводятся в unknown без автоматического повторения. Для 429 есть ограниченный повтор.
- Honeypot, проверки времени, строгие origin/размер/формат, постоянный rate limit по HMAC IP. Доверие X-Real-IP только от явно настроенного loopback proxy. Логи ошибок не содержат payload.
- Online backup и проверка восстановления по SHA-256/integrity/foreign keys/архиву документов. Восстановленные незавершённые задания карантинируются, чтобы не повторить уже доставленное уведомление.

Файлы и точная конфигурация: `backend/DURABLE.md`, `backend/durable-*.mjs`, `backend/durable.test.mjs`; `src/components/forms/OnlineLeadForm.tsx`, `src/lib/lead-context.ts`, изменения существующих CTA/client/attempt/exit-intent; `scripts/lead-flow-preparation.test.mjs`.
